# Security policy

## Project status

DatePipette is pre-alpha and must not yet be used with production credentials or sensitive business data.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, discussion, pull request, or chat transcript.

Use GitHub private vulnerability reporting when it is enabled for the repository. A dedicated security contact will be published before the first public release. If no private channel is available, contact the repository owner privately and share only enough information to establish a secure reporting channel.

Include, when safe:

- the affected component and version or commit;
- prerequisites and impact;
- minimal reproduction steps;
- whether credentials or real data may have been exposed; and
- a suggested mitigation, if known.

Do not access data that does not belong to you, degrade a system, or retain secrets while investigating.

## Supported versions

There are no supported production versions yet. A support table and disclosure process will be published with the first release candidate.
